## 2. 核心技术与业务术语

| 术语 | 建议定义 | 售前使用边界 |
|---|---|---|
| CRM | 客户关系管理系统及相关业务平台 | 不仅是联系人台账，也不自动代表所有营销、服务、数据平台能力 |
| SFA | 销售自动化/销售过程管理能力范畴 | 不一定是独立SKU名称 |
| SCRM | 社交化客户关系管理，强调社交触点、员工协同和客户经营 | 需说明依赖企业微信等生态能力及其授权 |
| MA | Marketing Automation，营销自动化 | 与营销云关系、功能包及授权需按正式目录确认 |
| CDP | Customer Data Platform，客户数据平台概念 | 不直接作为销售易某一具体SKU的唯一名称 |
| Data Cloud | 销售易资料中用于描述数据平台/数据能力的名称 | 正式命名、模块边界、部署和计费待核验 |
| NeoBI | 智能分析与可视化分析能力 | 与数据集成、湖仓存储等底层数据平台区分 |
| aPaaS | 应用平台即服务，支持应用构建和扩展 | 不等于所有代码定制、集成或第三方开发均包含 |
| 元数据 | 描述业务对象、字段、关系、页面、流程等结构的信息 | 具体元数据类型和开放范围需产品文档确认 |
| 业务语义本体 | 将业务实体、属性、关系、指标、规则、动作及流程语义化组织 | NeoAgent公开架构概念；不要宣称自动覆盖全部企业业务语义 |
| Data for AI | 面向AI应用的数据准备、语义理解和供给体系 | 对外使用官方四层架构：数据感知、语义提取、语义理解、Agent驱动 |
| Agent | 能理解任务、调用工具并执行一定业务步骤的智能体 | 能力受模型、工具、权限、数据、流程及人工确认机制约束 |
| Skill | 将工具、步骤、业务规则和输出标准封装为可复用任务能力 | 不等同于独立Agent；数量和可用范围以当前正式清单为准 |
| MCP | Model Context Protocol，连接模型与外部工具/数据的协议生态 | 协议支持不代表所有MCP服务均已预置、认证或商用可用 |
| API | 应用程序接口 | 有API不代表预置连接器、双向同步、无限调用或零实施成本 |
| OneID | 对多源客户身份进行识别、关联和统一管理的方法/能力概念 | 匹配规则、准确率、主键策略和产品实现范围需核验 |
| 客户360 | 围绕客户整合业务信息形成的统一视图 | 展示范围受数据源、权限、主数据和配置影响 |
| 线索 | 尚待进一步识别、培育和转化的潜在客户/需求记录 | 不与客户、联系人、商机概念混用 |
| 商机 | 有明确销售机会、阶段和预期成交过程的业务对象 | 阶段模型、预测字段和健康度算法需按客户配置/产品能力确认 |

## 3. 能力类型标准标签

| 标签 | 定义 | 证据要求 |
|---|---|---|
| 原生标准能力 | 正式产品版本中已发布并列入标准产品范围 | 最新正式手册/功能清单/发布说明 |
| 配置实现 | 通过产品现有管理界面、字段、流程、规则等配置完成 | 配置手册、版本和权限要求 |
| 低代码扩展 | 通过平台工具构建额外对象、页面、流程或应用 | aPaaS产品文档、授权和兼容性 |
| 定制开发 | 需要代码、自定义组件或专属业务逻辑开发 | 技术评估、工作量、验收与维护边界 |
| 第三方集成 | 依赖外部系统API、网络、认证、数据定义及双方配合 | 接口文档、兼容清单、联调结果 |
| 方案组合 | 多产品、数据、配置、规则和集成共同实现的行业方案 | 方案架构、能力映射及项目验证 |
| 规划中/待发布 | 已在规划或培训材料中出现，但没有正式发布证据 | 必须明确标记，不作为当前能力承诺 |
| 待核验 | 资料不足或相互冲突 | 不作为对外确定性承诺 |

## 4. 关键术语边界

- “实时”：必须明确事件触发、端到端延迟、数据源、刷新频率和异常机制；没有指标不写实时。
- “自动化”：说明触发条件、执行步骤、权限、失败处理及是否需要人工确认。
- “智能”：说明模型、数据、规则、工具和评价标准，不以“AI驱动”代替能力说明。
- “全渠道”：列明已支持渠道、版本、地区和接入方式，不泛化为所有渠道。
- “全球化”：多语言、海外网络节点、数据中心、属地部署、跨境合规分别表述。
- “统一”：说明统一的是身份、数据、指标、流程还是入口，不使用笼统“全域统一”。
- “闭环”：说明起点、终点、状态回写、责任人和异常处理。

## 5. 写作规则

1. 首次出现英文缩写时，给出中文解释。
2. 产品名称按官方标准大小写书写：NeoAgent 2.0、NeoBI、Data Cloud、aPaaS、MCP、API。
3. 产品、平台、能力、模块、SKU和方案不得互相替代。
4. 资料存在冲突时保留冲突记录，优先级按最新正式资料、官方帮助中心、官网公开资料、内部材料、历史对话依次处理。
5. 所有数字、版本、License、价格、配额、性能、SLA必须附来源和日期。
