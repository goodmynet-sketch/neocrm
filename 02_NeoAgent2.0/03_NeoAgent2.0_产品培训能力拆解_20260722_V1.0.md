## 1. 产品使用形态：AI 工作台

培训材料将 AI 工作台描述为独立工作空间，用户通过自然语言交代任务，避免在 CRM 页面中逐层寻找菜单。材料列出以下能力构成：

| 能力类别 | 培训材料描述 | 核验提醒 |
|---|---|---|
| 工具 | 查询/读写 CRM、搜索、知识库检索、文档解析与录入 | 对象范围、读写权限、数据范围需实机核验 |
| 文件与脚本 | 读写文件、运行脚本、处理数据、生成 Excel/图表 | 沙箱类型、文件格式、运行资源与安全边界需核验 |
| Skill | 将一套任务步骤、判断标准和风格封装为技能 | Skill 创建、发布、共享和权限以当前版本为准 |
| 任务 | 定时、周期性自动执行任务 | 触发范围、执行账号、失败重试、消息通知及配额需核验 |
| 记忆 | 记住偏好和上下文 | 记忆范围、持久性、清除策略与租户治理需核验 |

培训演示的典型交互包括：自然语言查询符合条件的商机并排序；通过文件提供服务商信息后生成 CRM 录入草案并经确认后落库。此类示例不能推导为所有对象和字段均支持同样的自动录入能力。

## 2. 培训材料列出的重点业务 Skills

材料第 8–9 页列出六类拳头 Skill：

1. 智能客户洞察：输入客户，输出背景、动态、需求及机会点摘要。
2. 商机健康度评估：输入商机，按 BANT / MEDDPICC / C139 等方法输出打分和多维评估。
3. 商机分析：分析商机进展、风险与建议。
4. 竞争分析：整理竞争对手情况与竞争策略。
5. 拜访准备：生成客户拜访话题清单与策略建议。
6. 工作日报/周报：辅助汇总工作记录并生成报告。

材料第 12 页称当时工具数量“20+”、预置 Skill 数量“40+”，并注明持续增加。**这是 2026-07-22 培训时点的内部口径，不是当前数量承诺。** 对外如需报数量，必须取得当前正式清单和统计口径。

## 3. 用户侧：个人 Skill 与数字员工构建

### 3.1 Skill 的定义

培训材料将工具定义为即插即用的原子能力，将 Skill 定义为把工具、业务逻辑、步骤、标准和风格打包成可复用任务能力。

Skill 的价值在于沉淀“怎么判断、怎么跟进、什么结果算完成”的业务方法，而不只是保存一段提示词或表单。

### 3.2 培训演示：本周待跟进 Skill

示例规则：
- 数据范围：当前用户负责的商机。
- 时间条件：本周关单。
- 跟进到位：该商机本周存在活动记录。
- 输出：待跟进、已跟进、未跟进数量，并列出未跟进商机。
- 任务：每周一自动运行并发送结果给用户。

此例可用于讲解“业务规则沉淀为 Skill + 定时任务”，但定时任务可用范围、通知渠道和调度策略仍需实机确认。

### 3.3 数字员工雏形

培训材料展示了大客户赢单链路：

客户选择（客户推荐/洞察）→ 建立关系（拜访准备）→ 商机建立（商机分析/健康度）→ 方案（竞争分析）→ 报价（方案/合同质检）→ 赢单复盘。

准确表述：培训材料强调将多个 Skill 按业务阶段串联，形成端到端工作链路的方向。不可直接表述为所有链路已经具备无人值守、自主规划和自动执行能力。

## 4. 管理员/交付者侧：业务语义、Skill 管理、智能任务

### 4.1 语义生成

培训材料描述：读取 CRM 结构，辅助生成对象/字段语义描述，再由管理员人工微调。语义配置是 AI 准确理解 CRM 对象、字段和业务规则的基础。

待核验：支持的实体类型、字段覆盖率、生成准确率、批量生成能力、版本发布与回滚方式。

### 4.2 Skill 管理

培训材料描述：
- 个人 Skill：个人创建和管理。
- 租户 Skill：管理员可将优秀 Skill 上架、启停并推广给全员。
- 管理员可查看个人 Skill，并对风险 Skill 强制停用；材料提及租户总开关。
- 材料提及 Skill Hub 为未来方向，不应按已发布能力承诺跨租户共享。

待核验：管理员角色要求、查看范围、强制停用行为、审计记录、Skill 版本管理与跨团队分发规则。

### 4.3 租户级智能任务

培训材料描述：管理员可绑定 Skill、筛选一批数据、设定范围，在后台按统一规范批量执行；可用于重点客户/项目定期健康度与风险评估。

待核验：批量上限、执行频率、并发、失败重试、数据权限继承、执行主体、额度消耗及消息推送方式。

## 5. AI 资源与额度管理：培训时点状态

培训材料第 22 页提到：
- 管理员给用户分配 AI 使用权限。
- 按月为用户配置额度档位（轻享/标准/畅享）。
- 可开放超额使用并按量另计。
- 原文明确注明“相关能力仍在建设中，以实际发布为准”，并要求结合 License、安全审计管理。

因此这部分不能直接作为当前商务收费、License 或超额计费政策。对外报价必须以最新正式定价单、合同和商务确认口径为准。

## 6. AI 使用方法与客户采用路径

培训材料建议用户从操作者转为指挥者：
- 会交代：明确目标、背景和约束。
- 懂委派：把重复、规则清晰的任务交给 Agent。
- 会把关：对外发送、数据修改、批量操作前检查结果。
- 重流程：从单步问答逐渐发展为查询、整理、更新、生成任务、提醒团队的多步链路。

建议客户采用路径：
1. 选定一个高频、痛点明确的小场景。
2. 配好业务语义与关键数据。
3. 陪同客户跑通一个可见成果。
4. 将客户做法沉淀为专属 Skill，再推广给团队。

## 8. 安全与边界

培训材料 Q&A 给出的口径包括 RBAC 权限继承、写入强制确认、内容审查/脱敏和可审计；并明确指出发邮件/消息等能力仍在规划，不能硬承诺。

对外使用时应拆分为：
- 已在当前租户/版本验证的权限控制与确认机制。
- 需要开通或配置的连接器、数据源和 License。
- 规划中的能力。
- 需要人工审核的高风险操作。

不可把培训材料中的概括性安全描述等同于完整安全认证、零风险承诺或全部功能默认开启。

## 9. 售前演示建议

推荐按“先看见结果，再理解底座”的顺序：

1. 自然语言查询 CRM 数据：展示 AI 理解业务对象、条件和结果格式。
2. 智能客户洞察：展示客户上下文整合和结构化洞察。
3. 商机健康度评估：展示方法论框架、风险项和下一步建议。
4. 自建 Skill：将企业自己的跟进标准沉淀成可复用能力。
5. 智能任务：展示定时/批量任务（仅在现场环境已验证后演示）。
6. 管理端：展示语义生成、Skill 分发、权限/额度/运行治理（仅展示当前可用项）。

每个演示场景均需准备：测试数据、前置 License、用户权限、连接器授权、执行结果检查和失败回退方案。不得使用不存在的客户记录或虚构真实姓名。
