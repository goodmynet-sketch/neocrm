## 1. 核心定义

NeoAgent 2.0 的公开产品表达以“业务语义本体 + Data for AI”为关键基础。业务语义本体的作用，是让 AI 不只识别自然语言字面含义，还能结合企业业务对象、字段含义、数据关系、指标口径、流程规则和业务动作理解任务。

Data for AI 的作用，是把企业内外部数据加工为 AI 可理解、可检索、可推理的语义化数据基础。二者共同支撑 Agent 在企业业务上下文中进行检索、分析、推理和任务执行。

**建议对外表述：**“销售易通过业务语义本体把 CRM 的对象、字段、关系、指标和业务规则组织成 AI 可理解的业务上下文，再结合 Data for AI 对多源数据进行语义化处理，使 Agent 能够围绕真实业务问题进行查询、分析并在授权范围内调用业务能力。”

## 2. 业务语义本体的构成

官网公开文章提及业务数据、指标定义、数据关系、业务动作、流程和规则等语义内容。内部技术/产品资料进一步使用实体、属性、关系、指标、规则、动作等术语。建议将其理解为以下逻辑构件：

| 语义构件 | 说明 | CRM 示例（仅作解释示例） | 需要核验 |
|---|---|---|---|
| 实体/对象 | 业务管理的核心对象 | 客户、联系人、商机、订单、服务工单 | 实际支持对象范围、标准/自定义对象覆盖 |
| 属性/字段 | 描述实体特征的数据项 | 客户行业、商机金额、预计成交日期 | 字段类型、枚举、公式字段、关联字段支持情况 |
| 关系 | 实体之间的业务关联 | 客户—联系人、客户—商机、订单—产品 | 多级关联、关系方向、跨对象查询限制 |
| 指标 | 具有明确统计口径的业务度量 | 商机转化率、销售额、回款额 | 指标定义来源、聚合口径、时间口径和权限 |
| 规则 | 业务判断条件与约束 | 商机阶段准入条件、客户分级规则 | 规则表达方式、冲突处理、版本管理 |
| 流程 | 业务活动的阶段和流转逻辑 | 线索转商机、商机审批、订单履约 | 是否可被 Agent 读取/触发/修改 |
| 动作 | 可调用的业务操作 | 查询客户、创建任务、更新记录 | 可调用动作白名单、授权、人工确认和审计 |

以上是对现有资料的概念归纳，不代表每一种构件均有独立配置页面或均支持自动生成。

## 3. Data for AI 四层公开架构

销售易官网文章公开描述 Data for AI 四层：

1. **数据感知：**连接并获取业务数据及相关信息，为后续理解提供输入。
2. **语义提取：**从数据中提取实体、属性、关系等语义信息。
3. **语义理解：**结合业务语义与上下文理解数据含义和业务问题。
4. **Agent 驱动：**将理解结果用于 Agent 的任务判断、分析和业务动作调用。

四层是官网对 Data for AI 的架构性解释，不应扩展成未经证实的具体技术组件、实时性指标、算法流程或部署拓扑。

### 3.1 与内部五层模型的关系

内部文件 `2026_neoagent2_0 (1).md` 使用过五层 Data for AI 表达，与官网四层公开架构存在差异。对外主口径统一采用官网四层；五层仅可作为内部方案分析模型，必须标注“内部分析框架”，不能宣称为官方产品架构。

## 4. 语义配置与生成：已知信息和边界

2026-07-22 培训材料描述：平台可读取 CRM 结构，辅助生成对象/字段语义描述，再由管理员人工调整。该过程说明语义配置可由系统辅助起步，但不能推导为自动完成全部业务本体建模。

当前待核验：
- 支持读取的 CRM 元数据类型及对象范围。
- 是否支持标准对象、自定义对象、字段、关联关系、指标、流程和规则。
- 语义生成是否支持批量、人工审核、发布、版本对比和回滚。
- 语义变更如何影响既有 Skill、Agent、查询和任务。
- 多语言字段、同义词、行业术语和组织内部简称如何维护。
- 语义准确性如何评测，错误语义如何发现和纠正。

## 5. 从语义到 Agent 执行的工作链路

建议以如下逻辑向客户解释，不将其误解为固定的底层运行时实现：

1. 用户提出业务问题或任务目标。
2. Agent 识别意图，并将自然语言映射到业务语义（实体、字段、关系、指标和规则）。
3. 系统在授权范围内检索 CRM 数据、知识库或已接入的数据源。
4. Agent 结合业务上下文进行分析、推理或生成建议。
5. 如任务需要执行动作，调用已授权的工具/业务能力。
6. 对高风险或敏感操作按配置进行人工确认，并保留相应执行记录。
7. 将结果反馈给用户，必要时沉淀为 Skill 或后续任务。

这是一种产品能力解释模型；具体调用编排、执行循环、确认节点和审计机制需按实际产品版本核验。

## 6. 与 CRM 业务场景的映射

| 业务问题 | 需要的语义理解 | 可能的数据/动作 | 输出价值 |
|---|---|---|---|
| 哪些商机本周需要重点跟进？ | 商机负责人、阶段、预计成交日期、活动记录、跟进规则 | 查询商机/活动、按规则筛选 | 待跟进清单和风险原因 |
| 某客户是否存在集团拓展机会？ | 集团/子公司关系、客户层级、历史交易、产品/部门关系 | 客户关系查询、历史订单与商机分析 | 潜在采购主体与拓展线索 |
| 商机健康度为什么下降？ | 阶段、决策链、预算、竞争、客户互动等评估维度 | CRM 数据检索、外部信息补充、评分规则 | 风险解释与推进建议 |
| 客户近期有哪些服务风险？ | 客户、设备/产品、工单、服务级别、满意度 | 服务记录查询、异常汇总 | 服务风险和客户经营建议 |

## 7. 数据来源、处理和权限：必须核验的边界

内部 Pitch Deck 提及 CRM、企业微信、知识库、互联网搜索、第三方数据源、外部业务系统及多模态数据等来源；官网文章也提及多源数据与相关 Agent 场景。资料尚不足以证明所有数据源均可在所有租户开箱即用。

对每个项目必须逐项确认：
- 数据源：CRM 内部对象、企业微信、文件、知识库、互联网数据、ERP 或第三方系统分别如何接入。
- 数据方式：API、连接器、文件导入、同步任务或实时查询；不能把“支持接入”直接等同于实时同步。
- 数据类型：文本、图片、附件、音视频及结构化数据的实际支持范围。
- 数据新鲜度：采集周期、索引刷新、缓存、延迟和失败补偿机制。
- 数据质量：去重、字段映射、实体匹配、主数据一致性和缺失值处理。
- 权限：是否继承 CRM 行级、字段级、组织级权限；外部系统权限如何映射。
- 安全：传输加密、脱敏、模型调用边界、数据留存、租户隔离和审计。

## 8. 与 Agent、Skill、工具的关系

- 业务语义本体：提供“理解业务”的上下文和规则。
- Data for AI：提供经过组织和语义化的数据基础。
- Agent：围绕目标组织理解、判断、规划和执行。
- Skill：封装可复用的业务任务方法、步骤与判断标准。
- 工具：提供查询、写入、搜索、解析、生成等原子能力。
- 任务：在指定时间或触发条件下发起执行。

这些是能力职责层面的区分，不代表产品 UI 中一定按上述顺序或层级呈现。

## 9. 对外表达的安全边界

可以说：
- 业务语义本体帮助 AI 理解 CRM 对象、字段、关系、指标和业务规则。
- Data for AI 的公开架构包括数据感知、语义提取、语义理解、Agent 驱动四层。
- 语义理解与可信数据基础共同支撑 Agent 在业务场景中进行检索、分析和任务执行。

不能未经核验就说：
- 所有企业数据已自动完成统一治理、主数据清洗或实时同步。
- 任意第三方系统均可零代码接入，且自动获得完整双向读写能力。
- Agent 能理解企业全部隐性规则，或无需配置即可达到专家级准确率。
- 所有数据源都严格继承原系统每一级权限，或所有调用均可完整审计。
- 官网四层架构等同于特定技术组件、数据库、向量引擎或部署拓扑。
