## 1. 能力定位

AI 工作台在内部产品资料中被描述为统一的 AI 任务入口：用户以自然语言提出业务目标，由底层语义理解、工具、Skill、任务和记忆等能力协同完成查询、分析、内容生成或业务操作。其价值不只是对话问答，而是把 AI 能力连接到 CRM 数据、业务规则与可执行动作。

**建议对外表述：**“AI 工作台为员工提供统一的自然语言工作入口，能够在权限范围内调用 CRM 与关联知识/工具，完成信息查询、分析总结、内容生成及经授权的业务操作；复杂任务可通过 Skill 沉淀为可复用流程，并结合任务机制减少重复工作。”

## 2. 工作台能力构成

| 能力单元 | 内部资料描述 | 可讲解的业务价值 | 关键核验点 |
|---|---|---|---|
| 工具 | CRM 查询/读写、搜索、知识库检索、文档解析、录入等原子能力 | 将 AI 与真实业务数据及动作连接 | 可调用工具清单、对象/字段范围、读写权限、外部连接器、调用审计 |
| Skill | 将工具、步骤、业务逻辑、判断标准和输出风格封装成可复用任务能力 | 沉淀个人经验与组织最佳实践 | 创建入口、发布范围、版本管理、共享权限、调试与停用 |
| 任务 | 定时、周期性任务；部分材料描述事件触发 | 自动处理周期性检查和重复工作 | 个人/组织任务边界、事件触发是否正式开放、调度频率、失败重试、通知方式 |
| 记忆 | 保存角色、偏好、历史上下文或任务记录 | 减少重复交代背景，提高连续任务体验 | 记忆范围、数据隔离、保留期限、用户控制、删除与审计机制 |
| 文件/脚本沙箱 | 读取/写入文件、运行脚本、数据计算，生成 Excel/图表/PDF 等 | 支持数据处理和结构化交付 | 文件格式、运行环境、资源限制、网络访问、安全隔离、文件保留策略 |
| 语义理解底座 | 将自然语言映射到 CRM 对象、字段、关系和规则 | 降低自然语言与 CRM 数据模型之间的理解偏差 | 语义覆盖范围、生成/修订/发布流程、权限继承及准确性评测 |

注：以上主要来自 2026-07-22 培训材料与 2026-09-10 内部 Pitch Deck。不同资料对任务触发能力的描述存在颗粒度差异；事件触发能力不能仅凭演示稿认定为当前租户普遍可用。

## 3. Skill：定义、结构与管理

### 3.1 定义

Skill 是将一项业务任务的目标、输入、工具调用、执行步骤、判断规则、输出格式和风格要求封装为可重复调用的能力。工具偏向“可调用的原子动作”，Skill 偏向“如何把动作组织成符合业务标准的任务”。

Skill 的价值在于沉淀“怎么判断、怎么推进、什么结果算完成”，而不只是保存一段提示词。

### 3.2 Skill 类型与适用边界

- 标准 Skill：内部资料描述为开箱即用的通用能力；当前完整清单、数量、版本和授权范围待核验。
- 个人/专属 Skill：员工结合个人经验和业务流程创建，用于个人工作方式沉淀。Pitch Deck 声称支持对话创建、修改和管理，并提到最多 30 个个人 Skill；该数量属于内部材料口径，必须在当前产品实机核验后才能对外引用。
- 团队/租户 Skill：培训材料描述管理员可集中管理个人与团队技能、启停和推广优秀 Skill。具体管理员权限、上架机制、团队可见范围需核验。

### 3.3 内部资料描述的生命周期操作

Pitch Deck 描述 Skill 支持创建、开启、关闭、复制、调试、删除，以及调用次数和使用状态追踪。建议将其作为待验收的功能点，而非未经验证的正式操作说明。

| 环节 | 业务控制问题 | 售前/实施核验清单 |
|---|---|---|
| 创建 | 谁能创建，是否支持自然语言创建 | 个人/管理员角色、输入方式、可引用工具与知识源 |
| 调试 | 如何验证输出与动作 | 测试数据、调试日志、错误提示、是否会真实写入业务数据 |
| 发布/启停 | 如何控制技能可用状态 | 发布范围、审批流程、停用后的存量任务处理 |
| 复制/复用 | 优秀经验如何推广 | 复制后归属、引用依赖、配置是否一并复制 |
| 删除 | 删除对历史调用与任务的影响 | 删除权限、软删除/硬删除、历史记录保留 |
| 运营追踪 | 如何衡量使用效果 | 调用次数、成功/失败状态、用户范围、日志留存和导出能力 |

## 4. 任务与自动化

### 4.1 个人定时任务

培训材料展示“本周待跟进”示例：筛选当前用户负责、预计本周关单的商机；以本周是否存在活动记录判断跟进情况；汇总待跟进、已跟进、未跟进数量并列出未跟进商机；按周运行并向用户反馈结果。

Pitch Deck 进一步描述可通过自然语言创建、修改、查看和停用个人定时任务。此类能力的当前可用范围、时区、执行身份、失败重试和通知渠道需实机核验。

### 4.2 组织级/租户级智能任务

培训材料描述管理员可将 Skill 与筛选条件绑定，对一批业务数据按统一规范在后台执行，可用于重点客户或项目的周期性健康度、风险评估。其核心价值是把统一方法论应用到一组业务对象，而非依赖每位员工逐个手动发起。

待核验：数据筛选器、最大批次、并发、执行频率、任务所有者、数据权限继承、失败重试、任务中断、额度消耗、通知及审计。

### 4.3 事件触发与敏感操作

Pitch Deck 描述当业务数据满足触发条件时，系统可识别并调用对应 Skill；并描述关键业务判断或高风险动作触发人工审核。培训材料对部分事件触发能力仍标记为建设/规划方向。故对外宜表述为“可结合自动化任务与人机协同机制设计业务推进方案”，不得笼统承诺所有业务事件均可触发 Agent 自动执行。

## 5. 业务场景映射

| 场景 | 输入 | Skill/工具组合 | 输出/动作 | 控制点 |
|---|---|---|---|---|
| 商机跟进检查 | 当前用户负责的商机、阶段、预计成交日期、活动记录 | CRM 查询 + 待跟进规则 Skill + 定时任务 | 待跟进清单、风险提示 | 数据权限、规则定义、任务周期 |
| 客户拜访准备 | 客户档案、联系人、历史活动、商机、服务记录 | 客户查询 + 知识检索 + 拜访准备 Skill | 客户摘要、关键话题、行动建议 | 数据完整性、外部信息来源、引用标识 |
| 商机健康诊断 | 商机信息、客户关系、决策链、预算、竞争情况 | 商机查询 + 健康度 Skill | 风险维度、问题根因、推进建议 | 评分模型、维度权重、解释性与人工复核 |
| 销售周报 | 活动、商机、漏斗和目标数据 | CRM 查询 + 汇总分析 Skill + 文件生成 | 结构化周报/图表 | 指标定义、统计周期、权限与口径一致性 |
| 客户档案辅助录入 | 上传文件/文本及 CRM 现有记录 | 文档解析 + 字段映射 + CRM 写入工具 | 结构化录入草稿或经确认写入 | 字段映射、重复校验、写入确认与审计 |

## 6. 安全、权限与资源治理

内部资料强调行动可见、权限控制、敏感操作人工审核，以及调用过程的审计追踪；Pitch Deck 还描述用户席位/AI 资源分级、临时额度、共享资源包等资源治理设计。但培训资料明确提示相关额度能力仍在建设中，以实际发布为准。因此：

- 不得将“轻享/标准/畅享”、临时追加额度、共享资源包或超额计费作为当前正式报价口径。
- 不得承诺所有写操作均自动执行；必须逐项核实是否需要人工确认。
- 不得将内部演示中“行动全程可见”扩展为所有模型输入、输出、工具调用均可导出或永久留存。
- 必须确认执行身份、CRM 原生权限继承、字段级权限、跨租户隔离、脱敏策略和审计留痕范围。

## 7. 售前演示建议

1. 从一个真实高频任务切入，例如“找出本周需要重点跟进的商机”，先展示自然语言查询。
2. 进一步展示 Skill 如何固化判断标准，例如“本周有活动记录才算跟进到位”。
3. 展示输出不仅有总结，还能定位到具体业务对象并提出下一步动作。
4. 如当前租户支持，再演示创建定时任务或组织级批量任务；如未核验，不现场承诺自动调度。
5. 对写入类动作明确展示人工确认、权限边界和操作记录。

## 8. 不可直接对外承诺的事项

- 当前标准 Skill 总数、个人 Skill 上限（Pitch Deck 提及 30 个）及所有租户的可用范围。
- 所有 Skill 均支持跨团队/跨租户共享、自动发布或版本回滚。
- 任意 CRM 对象、任意字段均可被 Agent 读取或写入。
- 所有事件均可触发任务，或任务可无限并发、无限批量运行。
- AI 资源分级、超额计费、共享资源包已成为正式商务政策。
- 所有敏感操作均已具备统一审批流、完整审计导出能力。
