## 1. 核心产品定位

NeoAgent 2.0 是销售易面向企业营销、销售、渠道与服务业务的 AI 原生产品体系/平台能力。官方公开资料强调：它不是在传统 CRM 上简单外挂聊天入口，而是通过业务语义本体、Data for AI、Agent 能力与业务流程结合，让 AI 能理解企业业务上下文，并在权限边界内辅助分析、建议和执行。

**对外简洁表述建议：**

> NeoAgent 2.0 以业务语义本体和可信数据为基础，通过 Agent 与 Skills 将 AI 能力嵌入营销、销售、渠道和服务业务流程，推动 CRM 从信息记录与流程管理，向主动辅助和业务任务执行演进。

注意：“自主执行”“结果交付”等表达应结合具体场景、授权、配置和人工审核机制说明，不应被理解为所有业务均可无人干预地自动完成。

## 2. 能力架构：当前可确认的主干

### 2.1 业务语义本体（Business Semantic Ontology）

官方公开资料说明，业务语义本体统一沉淀企业业务数据、指标定义、数据关系、业务动作、流程与规则，使 Agent 能够将自然语言指令映射到具体业务实体与业务逻辑，并基于业务阶段和指标提供建议。

知识库解释口径：
- 业务实体：客户、联系人、线索、商机、产品、合同、服务工单等（具体实体范围依产品模块与租户模型确认）。
- 业务属性：实体字段、状态、分类及相关描述。
- 业务关系：实体之间的关联关系与上下文。
- 业务指标：经营指标及其定义、计算口径。
- 业务规则：企业流程规则、业务约束与管理规范。
- 业务动作：可由系统/Agent 调用的业务操作或流程动作，具体动作与权限需逐项确认。

### 2.2 Data for AI

官方资料说明 NeoAgent 2.0 依托 Data Cloud 增强非结构化数据处理，形成数据感知、语义提取、语义理解、Agent 驱动的四层数据处理链路。

| 层次 | 官方公开资料描述 | 知识库解释 |
|---|---|---|
| 数据感知 | 整合拜访录音、活动记录、会议内容、邮件往来、企微对话等 | 在授权范围内接入业务互动与业务数据 |
| 语义提取 | 对结构化/非结构化数据进行语义特征提取 | 从文本、语音及业务数据中提取信息与特征 |
| 语义理解 | 形成统一语义层与语义索引 | 使数据能按业务语义被检索和理解 |
| Agent 驱动 | Agent 基于业务语义进行检索、推理与执行 | 为业务智能体提供数据上下文和执行依据 |

重要边界：白皮书草稿中出现的多模态图纸识别、跨语种知识图谱、ERP/MES 全域实时数据、离线知识库等内容，若无对应正式产品资料或项目验证，不得直接视为 NeoAgent 2.0 标准开箱能力。

### 2.3 Agent + Skills

官方产品介绍与内部产品材料共同体现 Agent 与 Skills 是核心组织方式。Agent 根据业务目标组织任务，Skills 封装可复用任务能力。

当前知识口径：
- 标准 Skills：用于承载通用任务能力；具体名称、数量、版本和可用范围须以当前产品环境/正式清单为准。
- 企业专属 Skills：结合企业自身产品、流程、规则、字段、知识与岗位要求配置；不得把某个客户定制 Skill 宣称为全产品标准能力。
- Skills 生命周期：内部产品介绍材料提到创建、开启/关闭、复制、调试、删除、团队管理和调用效果追踪。该细节目前属于内部产品材料支持，需以当前版本帮助中心/产品实机复核后升级为已核验操作知识。
- Agent 的执行范围取决于授权数据、可用工具、业务流程、租户配置和人工确认要求。

## 3. 官方公开可确认的业务场景

### 3.1 销售经理 Agent

官方产品文章明确介绍四类能力：
1. 智能客户洞察：结合内外部数据，输出客户经营、组织变化、竞争差异等洞察。
2. 商机健康度评估：输出结构化、可解释、可行动的商机评估。
3. 下一步行动建议（NBA）：结合商机阶段与客户互动情况推荐跟进动作。
4. 资源推荐：推荐专家、相似赢单案例及材料资源。

### 3.2 企微会话 Agent

官方产品文章明确介绍：
- 识别会话热点话题，辅助推荐营销素材。
- 根据客户对话辅助打标签、补全画像。
- 基于客户提问推荐销售话术。
- 总结会话内容并形成客户业务报告。
- 辅助服务会话质检。

使用前提和限制：涉及会话存档、企业微信接口、员工授权、数据权限和相应 License 的能力必须单独确认；不能把会话 Agent 能力等同于默认获得所有聊天数据。

### 3.3 智能字段、智能流程与可观测性

官方公开文章提到：
- 智能字段：读取记录内外的文本、图片、附件或网络信息，进行识别、分类、评估，并将结果写回字段。
- 智能流程：在工作流节点调用 AI，支持录入、总结、查询等任务；管理员可配置可复用提示词模板。
- 可观测性：智能体运营看板、Token 流量监控与提醒、用户使用日志及 AI 返回内容记录。

具体触发条件、字段类型、节点范围、调用计费、日志保留期限、看板指标、告警策略等均待帮助中心/正式规格核验。

## 4. 平台及生态能力

官网产品导航将 NeoAgent 2.0 列为平台型产品，并列出销售 Agent、服务 Agent、业务专项子 Agent、Agent 开发平台；同时将 aPaaS、智能分析云、Data Cloud 分列为平台型产品。

内部 2026 NeoAgent 2.0 pitch deck 还提及统一 AI 工作台、Agent 资产、记忆与上下文、模型接入、MCP/A2A/API 生态连接、TokenHub、权限与审计等。由于这些信息来自内部产品介绍材料，部分能力的当前可用状态、产品归属和正式命名需产研/产品负责人核验。

不可混淆：
- NeoAgent 2.0：AI 原生产品体系/智能体平台能力。
- Data Cloud：统一数据接入、元数据、数据服务与治理等数据平台能力；与 Data for AI 概念相关但不能简单等同。
- aPaaS：低代码应用开发与扩展平台。
- 智能分析云：BI 与分析能力。
- MCP/A2A/API：生态接入或能力开放方式，具体协议支持和操作权限须逐项核验。

## 5. 安全、权限与人机协同原则

可作为方案设计原则使用，但不得超出正式产品/合同承诺：
- AI 读取数据应受用户身份、CRM 数据权限和已授权连接范围约束。
- 外部应用连接应核对授权范围、授权主体、可撤销机制及数据使用边界。
- 对报价、合同条款、价格承诺、审批、客户正式通知、财务处理等高风险操作，默认设计人工复核/授权。
- 对 AI 输入、输出、工具调用和业务写回，应核实产品是否提供相应审计日志及其范围。
- 数据跨境、数据中心地域、模型调用路径、数据留存、训练用途和合规认证，必须取得正式安全/合规材料；营销文案不能作为合同承诺。

## 7. 暂不纳入标准能力基线的白皮书场景

V5.15 白皮书草稿中涉及的以下场景，当前先作为行业方案/POC 假设管理：
- 海外工商情报自动爬取、海关提单、制裁筛查和自动生成潜客名单。
- 复杂招标文件自动解析、技术偏差表、历史项目匹配及研发协同任务派发。
- 海外渠道返利自动核算、库存实时读取和跨系统交易执行。
- 多语种模拟陪练并与 CRM 操作授权等级联动。
- 现场拍照识别设备元件、离线知识检索、三维维修指导和 ERP 自动扣减备件。
- 全球跨区域经营归因、预测、自动督办及多系统产销协同。

以上场景需逐项标注 CRM 原生、NeoAgent AI、外部数据/系统集成、客户专属配置、人工审批五类组成，并通过 POC 验证后才能调整状态。
