## 3. 每条知识的标准元数据

- 知识编号、产品归属、一级模块、功能模块
- 标题、功能说明、业务价值
- 配置前提、权限要求、操作步骤
- 适用版本、发布日期、文档更新时间
- 能力类型：原生标准能力、配置能力、扩展/定制、第三方集成、规划/待确认
- 限制与注意事项
- 来源等级、原始文件名、原始 URL、页码或章节
- 核验状态：已核验、部分核验、待核验、已过期
- 最近核验日期、变更记录

## 4. 产品事实判定规则

1. 区分产品原生能力、配置能力、扩展定制能力和第三方集成能力。
2. 区分已发布能力、版本规划、方案构想和未验证推断。
3. 未找到正式依据时，不推断为标准功能；标记待核验并说明缺失证据。
4. 新资料不能静默覆盖旧资料；保留旧版并记录替代关系、生效日期和差异。
5. 定价、授权、配额、性能、SLA、安全合规、部署区域等高风险口径必须使用对应正式资料核验。
6. 客户项目事实严格隔离；仅抽取有明确来源和适用边界的通用方法论进入行业知识。
7. 内部方案草稿中推演的技术架构和应用场景，不得自动升级为正式产品能力。
